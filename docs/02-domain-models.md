# Domain Models & Database Schema

## Domain Models (`internal/domain/models.go`)

All domain models are plain Go structs with `json` tags. They represent the in-memory data contract between packages and are separate from the SQL rows and input structs in `internal/storage`. Optional numeric fields are pointers (`*float64`) so "unset" is distinguishable from `0`; `domain.Float(v)` builds one. All timestamps are UTC. `domain.NewID()` returns a random version-4 UUID string.

---

### Enumerations

Enumerations are string types with typed constants.

#### `TradingMode`
```go
type TradingMode string

const (
	ModeManual         TradingMode = "manual"
	ModeSemiAutomated  TradingMode = "semi_automated"
	ModeFullyAutomated TradingMode = "fully_automated"
)
```

#### `TradingEnvironment`
```go
type TradingEnvironment string

const (
	EnvPaper TradingEnvironment = "paper"
	EnvLive  TradingEnvironment = "live"
)
```

#### `Direction`
```go
type Direction string

const (
	Long  Direction = "long"  // buy / open long / close short
	Short Direction = "short" // sell / close long / open paper short
)
```

### Core Trade Lifecycle Models

#### `TradeIdea`
Generated by a strategy. Represents a signal before risk evaluation.

| Field (JSON) | Go type | Description |
|---|---|---|
| `ID` (`id`) | string (UUID) | Unique identifier, set by the strategy with `domain.NewID()` |
| `StrategyID` (`strategy_id`) | string | Identifier of the strategy that produced this idea |
| `Market` (`market`) | string | Trading pair, e.g. `"BTC/EUR"` |
| `Direction` (`direction`) | Direction | `Long` or `Short` |
| `Thesis` (`thesis`) | string | Human-readable rationale (appended by LLM if available) |
| `SupportingSignals` (`supporting_signals`) | map[string]any | Raw signal values (momentum, news sentiment, price data) |
| `Confidence` (`confidence`) | float64 | 0.0–1.0 base confidence. Modified by LLM and learner |
| `EntryPlan` (`entry_plan`) | string | Strategy's entry description |
| `ExitPlan` (`exit_plan`) | string | Strategy's exit description |
| `StopOrInvalidation` (`stop_or_invalidation`) | string | Invalidation condition |
| `PositionSizingProposal` (`position_sizing_proposal`) | float64 | Fraction of equity to allocate (e.g. 0.20 = 20%) |
| `ModeEligibility` (`mode_eligibility`) | []TradingMode | Which modes this idea can execute in |

The struct has no creation timestamp; `trade_ideas.created_at` is stamped by `Repository.SaveTradeIdea` on first insert.

#### `RiskDecision`
Output of `risk.Engine.EvaluateTrade()`.

| Field (JSON) | Go type | Description |
|---|---|---|
| `TradeIdeaID` (`trade_idea_id`) | string | ID of the evaluated `TradeIdea` |
| `Approved` (`approved`) | bool | Whether the trade passed all risk checks |
| `Reason` (`reason`) | string | Human-readable explanation of the decision |
| `AdjustedSizing` (`adjusted_sizing`) | *float64 | Optional sizing override (not currently used) |
| `ProposedSize` (`proposed_size_eur`) | *float64 | Exact quote-currency amount the risk engine approved |
| `Timestamp` (`timestamp`) | time.Time | UTC evaluation time |

#### `ApprovalRequest`
Represents a pending item in the semi-automated approval queue.

| Field (JSON) | Go type | Description |
|---|---|---|
| `ID` (`id`) | string (UUID) | Unique request identifier |
| `TradeIdea` (`trade_idea`) | TradeIdea | The signal awaiting approval |
| `RiskDecision` (`risk_decision`) | RiskDecision | The passing risk evaluation |
| `ExpiresAt` (`expires_at`) | time.Time | Auto-expires 30 minutes after creation (`approval.DefaultTTL`) |
| `Status` (`status`) | string | `"pending"`, `"approved"`, `"rejected"`, `"expired"` |

The creation time is stored only in the `approval_requests.created_at` column.

#### `ExecutionIntent`
Created when an approval is acted upon or in fully-automated mode. Input to the execution engine.

| Field (JSON) | Go type | Description |
|---|---|---|
| `ApprovalRequestID` (`approval_request_id`) | string | Source approval ID, or `"auto"` / `"stop_loss"` |
| `Market` (`market`) | string | Trading pair |
| `Direction` (`direction`) | Direction | `Long` or `Short` |
| `Size` (`size`) | float64 | Size in base asset units (e.g. BTC, ETH); sent to Kraken as `volume` |
| `Price` (`price`) | *float64 | Optional limit price |

#### `OrderRecord`
Created by the execution engine after a fill attempt.

| Field (JSON) | Go type | Description |
|---|---|---|
| `ID` (`id`) | string (UUID) | Order identifier |
| `Market` (`market`) | string | Trading pair |
| `Direction` (`direction`) | Direction | `Long` or `Short` |
| `Size` (`size`) | float64 | Base asset quantity |
| `Price` (`price`) | float64 | Fill price (after slippage) |
| `Status` (`status`) | string | `"pending"`, `"filled"`, `"cancelled"`, `"rejected"` (live orders may also be `"submitted"`) |
| `Timestamp` (`timestamp`) | time.Time | Fill time |
| `ExchangeOrderID` (`exchange_order_id`) | string | Kraken order ID for live orders, or a local rejection reason |
| `PositionID` (`position_id`) | string | Links to the affected `open_positions` row |

#### `FillRecord`
Individual fill details (currently 1:1 with orders).

| Field (JSON) | Go type | Description |
|---|---|---|
| `OrderID` (`order_id`) | string | Parent order |
| `FillPrice` (`fill_price`) | float64 | Actual execution price |
| `FillSize` (`fill_size`) | float64 | Quantity filled |
| `Fee` (`fee`) | float64 | Fee charged in quote currency |
| `Timestamp` (`timestamp`) | time.Time | Fill time |

### Position & Portfolio Models

#### `PositionRecord`
Represents a single open trade. The paper engine stores these in a `map[string]domain.PositionRecord` keyed by `position_id`, plus a slice that preserves insertion order.

| Field (JSON) | Go type | Description |
|---|---|---|
| `PositionID` (`position_id`) | string (UUID) | Primary key. Auto-generated; unique per trade, not per market |
| `Market` (`market`) | string | Trading pair |
| `Size` (`size`) | float64 | Signed quantity: positive = long, negative = short (paper) |
| `AvgPrice` (`avg_price`) | float64 | Average entry price |
| `UnrealizedPnL` (`unrealized_pnl`) | float64 | Mark-to-market P&L. Updated every tick via `paper.Engine.UpdateMarkPrices()` |
| `Timestamp` (`timestamp`) | time.Time | Position open time |

Multiple `PositionRecord` values can exist for the same market, but the risk engine and execution engine together enforce the one-position-per-pair rule going forward.

#### `EquitySnapshot`
Periodic equity measurement for the equity curve chart.

| Field (JSON) | Go type | Description |
|---|---|---|
| `TotalEquity` (`total_equity`) | float64 | Cash + mark-to-market value of all open positions |
| `Cash` (`cash`) | float64 | Liquid cash available |
| `PositionsValue` (`positions_value`) | float64 | Sum of position values at current market prices |
| `Timestamp` (`timestamp`) | time.Time | Snapshot time |

The dashboard uses `portfolio.EquitySnapshot` (`internal/portfolio`), which carries the same values with an ISO-8601 string timestamp.

### News & Market Models

#### `MarketSnapshot`
One price observation from the Kraken ticker (REST or WebSocket v2).

| Field (JSON) | Go type | Description |
|---|---|---|
| `Symbol` (`symbol`) | string | Internal pair, e.g. `"BTC/EUR"` |
| `Timestamp` (`timestamp`) | time.Time | Observation time |
| `Price` (`price`) | float64 | Last/mid price |
| `Volume` / `Bid` / `Ask` | *float64 | Optional 24-hour volume and best bid/ask |

#### `Candle`
One OHLC bar: `T` (Unix seconds), `O`, `H`, `L`, `C`, `V`, serialised as `t`, `o`, `h`, `l`, `c`, `v`.

#### `NewsItem`
Raw news article from an RSS feed or the Fear & Greed adapter.

| Field (JSON) | Go type | Description |
|---|---|---|
| `ID` (`id`) | string | 16-hex-character ID: `sha256(title + url)` truncated (`news.StableID`), stable across restarts |
| `Source` (`source`) | string | Feed source name (`"CoinDesk"`, `"CoinTelegraph"`) |
| `Title` (`title`) | string | Article headline |
| `Content` (`content`) | string | RSS description/body. The dashboard and LLM prompts use a 200-character summary |
| `PublishedAt` (`published_at`) | time.Time | Article publication time, normalised to UTC for safe cross-source sorting |
| `URL` (`url`) | string | Article URL (may be empty) |

#### `NewsSignal`
Processed sentiment signal extracted from a `NewsItem`. `news.DefaultSignal()` returns a neutral value; there is no sentiment logic beyond that.

#### `EventSignal` and `UniverseSnapshot`
`EventSignal` describes a detected market event (type, affected assets, severity) and is currently unused. `UniverseSnapshot` is the resolved market universe (`FixedMarkets`, `DynamicMarkets`, `ResolverSource`, `ResolvedAt`, `Mapping`) returned by `universe.Resolver.ResolveUniverse()`.

## Database Schema (`internal/storage/database.go`)

The schema is defined as raw `CREATE TABLE IF NOT EXISTS` statements that reproduce the DDL SQLAlchemy generated for the Python version, so an existing `trading_bot.db` opens and keeps working. The database is a single SQLite file (`DATABASE_PATH`, default `./trading_bot.db`) opened through `modernc.org/sqlite` with `busy_timeout(5000)`, `journal_mode(WAL)` and `foreign_keys` off (SQLAlchemy never enabled it). Migrations are applied automatically at start-up by `storage.Open()`.

`*storage.Repository` is the single gateway for all reads and writes. Its methods take a `context.Context` first, for example `SaveTradeIdea(ctx, idea, signalContext)`, `SaveOrder(ctx, order, SaveOrderOptions{...})`, and `GetLatestCash(ctx)`.

---

### Table: `order_records`

Primary table for the trade ledger. Filled paper orders and accepted live orders create rows here. Execution-level rejections are stored separately in `rejected_trades` so rejected intents do not pollute the operational ledger.

| Column | Type | Notes |
|---|---|---|
| `id` | VARCHAR PK | UUID from `OrderRecord.ID` |
| `approval_request_id` | VARCHAR nullable | `"auto"`, `"stop_loss"`, a UUID, or NULL |
| `market` | VARCHAR (indexed) | e.g. `"BTC/EUR"` |
| `direction` | VARCHAR | `"long"` or `"short"` |
| `size` | FLOAT | Base asset quantity |
| `price` | FLOAT | Fill price |
| `fee` | FLOAT nullable | Fee in quote currency |
| `status` | VARCHAR | `"filled"`, `"pending"`, or `"submitted"` |
| `environment` | VARCHAR | `"paper"` or `"live"` |
| `timestamp` | DATETIME | Fill time |
| `exchange_order_id` | VARCHAR nullable | Kraken transaction ID for live orders |
| `position_id` | VARCHAR nullable (indexed) | Links to `open_positions.position_id`; shared between the opening and closing orders |
| `pnl` | FLOAT nullable | Realised P&L. Set only on close orders (`Repository.UpdateOrderPnL`) |
| `trade_idea_id` | VARCHAR nullable (indexed) | Signal that triggered the accepted order |

**Derived field `source`** (computed by `Repository.GetTradeLedger`, not stored):
- `"stop-loss"` — when `approval_request_id == "stop_loss"`
- `"auto"` — when `approval_request_id == "auto"`
- `"manual"` — when `approval_request_id` is any other value
- `"system"` — when `approval_request_id` is NULL or empty

**Derived field `trade_type`** (computed by `Repository.GetTradeLedger`, not stored):
- `"open"` — the earliest order for a `position_id` (or an order with no `position_id`)
- `"close"` — any later order for the same `position_id`

A close order without its own `trade_idea_id` inherits the opening order's strategy for display.

### Table: `equity_snapshots`

Time series of total portfolio equity. Written every strategy tick (~30 seconds) and by the equity ticker loop (every 10 seconds); trimmed to 17,280 rows (~48 hours at 10 seconds, `storage.MaxEquityRows`).

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK (auto) | |
| `total_equity` | FLOAT | Cash + positions at mark price |
| `cash` | FLOAT | Liquid cash only |
| `positions_value` | FLOAT | Mark-to-market positions value |
| `timestamp` | DATETIME | Snapshot time |

On restart, `Repository.GetLatestCash()` is called to restore the paper engine's cash (`paper.Engine.SetCash`) from the most recent snapshot. This prevents cash from being reset to `STARTING_CAPITAL` after a restart.

### Table: `market_snapshots`

Rolling price tick history. Trimmed to 5,760 rows per symbol (~48 hours at 30-second intervals, `storage.MaxPriceRowsPerSymbol`). Indexed on `(symbol, timestamp)`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK (auto) | |
| `symbol` | VARCHAR | Trading pair |
| `timestamp` | DATETIME | Tick time |
| `price` | FLOAT | Price from the Kraken ticker |
| `volume` | FLOAT nullable | Volume (not currently populated) |

When the strategy loop boots (after resolving and validating the market universe), the last 60 ticks per symbol are loaded into the in-memory price history (`App.priceHistory`) to give the strategy and indicator package warm-started history.

## Auto-Migration Logic

`storage.Open()` calls `migrate()` in `internal/storage/database.go`, which runs these steps in order:

1. **Legacy `open_positions`** — if the table exists without a `position_id` column (old market-as-PK schema), it is dropped and recreated.

2. **Create tables** — every `CREATE TABLE IF NOT EXISTS` statement runs, so new tables (`activity_log`, `risk_rejections`, `control_state`, `llm_briefings`, `llm_reflections`, `risk_state`, `rejected_trades`, …) appear on older databases.

3. **Add missing columns** via `ALTER TABLE … ADD COLUMN`:
   - `order_records`: `position_id`, `pnl`, `trade_idea_id`
   - `trade_ideas`: `momentum_pct`, `indicators`, `llm_*`, `news_context`, `risk_*`
   - `signal_outcomes`: `trade_idea_id`, `position_id`, `closing_trade_idea_id`
   - `open_positions`: `trade_idea_id`
   - `control_state`: `live_markets`, `selected_strategy`

4. **Indexes** — every index is created with `CREATE INDEX IF NOT EXISTS`, skipping any whose columns are missing on a legacy table.

5. **Schema version** — `schema_version` is created and set to the current version.

No manual migration step is required. There is no downgrade path.
