# Domain Models & Database Schema

## Domain Models (`backend/domain/models.py`)

All domain models are Pydantic v2 `BaseModel` classes. They represent the in-memory data contract between modules and are separate from the SQLAlchemy ORM models used for persistence.

---

### Enumerations

#### `TradingMode`
```python
class TradingMode(str, Enum):
    MANUAL           = "manual"
    SEMI_AUTOMATED   = "semi_automated"
    FULLY_AUTOMATED  = "fully_automated"
```

#### `TradingEnvironment`
```python
class TradingEnvironment(str, Enum):
    PAPER = "paper"
    LIVE  = "live"
```

#### `Direction`
```python
class Direction(str, Enum):
    LONG  = "long"    # buy / open long / close short
    SHORT = "short"   # sell / close long / open paper short
```

### Core Trade Lifecycle Models

#### `TradeIdea`
Generated by a strategy. Represents a signal before risk evaluation.

| Field | Type | Description |
|---|---|---|
| `id` | str (UUID) | Auto-generated unique identifier |
| `strategy_id` | str | Identifier of the strategy that produced this idea |
| `market` | str | Trading pair, e.g. `"BTC/EUR"` |
| `direction` | Direction | LONG or SHORT |
| `thesis` | str | Human-readable rationale (appended by LLM if available) |
| `supporting_signals` | dict | Raw signal values (momentum, news sentiment, price data) |
| `confidence` | float | 0.0–1.0 base confidence. Modified by LLM and learner |
| `entry_plan` | str | Strategy's entry description |
| `exit_plan` | str | Strategy's exit description |
| `stop_or_invalidation` | str | Invalidation condition |
| `position_sizing_proposal` | float | Fraction of equity to allocate (e.g. 0.20 = 20%) |
| `mode_eligibility` | list[TradingMode] | Which modes this idea can execute in |
| `created_at` | datetime | UTC creation timestamp |

#### `RiskDecision`
Output of `RiskEngine.evaluate_trade()`.

| Field | Type | Description |
|---|---|---|
| `trade_idea_id` | str | ID of the evaluated `TradeIdea` |
| `approved` | bool | Whether the trade passed all risk checks |
| `reason` | str | Human-readable explanation of the decision |
| `adjusted_sizing` | float \| None | Optional sizing override (not currently used) |
| `timestamp` | datetime | UTC evaluation time |

#### `ApprovalRequest`
Represents a pending item in the semi-automated approval queue.

| Field | Type | Description |
|---|---|---|
| `id` | str (UUID) | Unique request identifier |
| `trade_idea` | TradeIdea | The signal awaiting approval |
| `risk_decision` | RiskDecision | The passing risk evaluation |
| `status` | str | `"pending"`, `"approved"`, `"rejected"`, `"expired"` |
| `created_at` | datetime | UTC creation time |
| `expires_at` | datetime | Auto-expires 30 minutes after creation |

#### `ExecutionIntent`
Created when an approval is acted upon or in fully-automated mode. Input to the execution engine.

| Field | Type | Description |
|---|---|---|
| `approval_request_id` | str | Source approval ID, or `"auto"` / `"stop_loss"` |
| `market` | str | Trading pair |
| `direction` | Direction | LONG or SHORT |
| `size` | float | Size in base asset units (e.g. BTC, ETH) |

#### `OrderRecord`
Created by the execution engine after a fill attempt.

| Field | Type | Description |
|---|---|---|
| `id` | str (UUID) | Order identifier |
| `market` | str | Trading pair |
| `direction` | Direction | LONG or SHORT |
| `size` | float | Base asset quantity |
| `price` | float | Fill price (after slippage) |
| `status` | str | `"filled"` or `"rejected"` |
| `timestamp` | datetime | Fill time |
| `position_id` | str \| None | Links to the affected `OpenPositionModel` row |

#### `FillRecord`
Individual fill details (currently 1:1 with orders).

| Field | Type | Description |
|---|---|---|
| `order_id` | str | Parent order |
| `fill_price` | float | Actual execution price |
| `fill_size` | float | Quantity filled |
| `fee` | float | Fee charged in quote currency |
| `timestamp` | datetime | Fill time |

### Position & Portfolio Models

#### `PositionRecord`
Represents a single open trade. The execution engine stores these in a `Dict[position_id, PositionRecord]`.

| Field | Type | Description |
|---|---|---|
| `position_id` | str (UUID) | Primary key. Auto-generated; unique per trade, not per market |
| `market` | str | Trading pair |
| `size` | float | Signed quantity: positive = long, negative = short (paper) |
| `avg_price` | float | Average entry price |
| `unrealized_pnl` | float | Mark-to-market P&L. Updated every tick via `update_mark_prices()` |
| `timestamp` | datetime | Position open time |

Multiple `PositionRecord` instances can exist for the same market, but the risk engine and execution engine together enforce the one-position-per-pair rule going forward.

#### `EquitySnapshot`
Periodic equity measurement for the equity curve chart.

| Field | Type | Description |
|---|---|---|
| `total_equity` | float | Cash + mark-to-market value of all open positions |
| `cash` | float | Liquid cash available |
| `positions_value` | float | Sum of position values at current market prices |
| `timestamp` | datetime | Snapshot time |

---

### News & Market Models

#### `NewsItem`
Raw news article from an RSS feed.

| Field | Type | Description |
|---|---|---|
| `id` | str | SHA-based ID derived from URL |
| `source` | str | Feed source name (`"CoinDesk"`, `"CoinTelegraph"`) |
| `title` | str | Article headline |
| `content` | str | RSS description/body (truncated to 200 chars in memory) |
| `published_at` | datetime | Article publication time, normalised to timezone-aware UTC for safe cross-source sorting |
| `url` | str \| None | Article URL |

#### `NewsSignal`
Processed sentiment signal extracted from a `NewsItem`. Currently populated structurally but sentiment logic is a stub.

## Database Schema (`backend/storage/models.py`)

All tables use SQLAlchemy's `DeclarativeBase`. The database is a single SQLite file (`kraken_bot.db`). Migrations are applied automatically at startup via `init_database()`.

---

### Table: `order_records`

Primary table for the trade ledger. Every execution attempt creates a row.

| Column | Type | Notes |
|---|---|---|
| `id` | String PK | UUID from `OrderRecord.id` |
| `approval_request_id` | String nullable | `"auto"`, `"stop_loss"`, a UUID, or NULL |
| `market` | String (indexed) | e.g. `"BTC/EUR"` |
| `direction` | String | `"long"` or `"short"` |
| `size` | Float | Base asset quantity |
| `price` | Float | Fill price |
| `fee` | Float nullable | Fee in quote currency |
| `status` | String | `"filled"` or `"rejected"` |
| `environment` | String | `"paper"` or `"live"` |
| `timestamp` | DateTime | Fill time |
| `exchange_order_id` | String nullable | Reserved for live exchange order IDs |
| `position_id` | String nullable (indexed) | Links to `open_positions.position_id`; shared between the opening BUY and closing SELL |
| `pnl` | Float nullable | Realised P&L. Set only on close orders (SHORT that closes a LONG) |

**Derived field `source`** (computed in repository, not stored):
- `"stop-loss"` — when `approval_request_id == "stop_loss"`
- `"auto"` — when `approval_request_id == "auto"`
- `"manual"` — when `approval_request_id` is any other UUID
- `"system"` — when `approval_request_id` is NULL

**Derived field `trade_type`** (computed in repository, not stored):
- `"open"` — when `direction == "long"`
- `"close"` — when `direction == "short"`

### Table: `open_positions`

One row per currently open trade. Rows are created on BUY fills and deleted on SELL fills or stop-loss closure.

| Column | Type | Notes |
|---|---|---|
| `position_id` | String PK | UUID matching `order_records.position_id` |
| `market` | String (indexed) | Trading pair. Not unique — multiple rows per market are structurally possible (currently one per pair enforced by engine) |
| `size` | Float | Signed size. Updated on partial fills (not currently used) |
| `avg_price` | Float | Average entry price |
| `signal_confidence` | Float nullable | Confidence at signal generation time |
| `strategy_id` | String nullable | Strategy that generated the signal |
| `direction` | String nullable | `"long"` or `"short"` |
| `trade_idea_id` | String nullable (indexed) | UUID of the `trade_ideas` row that opened this position. Persisted so the link survives restarts. |
| `unrealized_pnl` | Float | Mark-to-market. Not regularly updated in DB; use in-memory value |
| `opened_at` | DateTime | Position creation time |
| `updated_at` | DateTime | Last update time (auto-updated on merge) |

### Table: `signal_outcomes`

Written when a position is fully closed. This is the learning dataset used by `PerformanceLearner` and the LLM reflection loop.

| Column | Type | Notes |
|---|---|---|
| `id` | Integer PK (auto) | |
| `strategy_id` | String (indexed) | Source strategy |
| `market` | String (indexed) | Trading pair |
| `direction` | String | `"long"` or `"short"` |
| `entry_price` | Float | Average entry price |
| `exit_price` | Float | Close price |
| `size` | Float | Absolute quantity |
| `pnl` | Float | Realised P&L in quote currency |
| `pnl_pct` | Float | P&L as a fraction of entry value |
| `confidence_at_entry` | Float nullable | Signal confidence when the trade was entered |
| `exit_reason` | String | `"stop_loss"` · `"auto"` · `"manual_approve"` · `"manual_close"` · `"operator_reset"` |
| `entry_at` | DateTime | Position open time |
| `exit_at` | DateTime | Position close time |
| `trade_idea_id` | String nullable (indexed) | Opening signal that created the position |
| `closing_trade_idea_id` | String nullable (indexed) | Signal that triggered the close (`auto` / `manual_approve` only; empty for stop-loss and manual UI closes) |

### Table: `equity_snapshots`

Time series of total portfolio equity. Written every strategy tick (~30 seconds).

| Column | Type | Notes |
|---|---|---|
| `id` | Integer PK (auto) | |
| `total_equity` | Float | Cash + positions at mark price |
| `cash` | Float | Liquid cash only |
| `positions_value` | Float | Mark-to-market positions value |
| `timestamp` | DateTime | Snapshot time |

On restart, `get_latest_cash()` is called to restore `PaperExecutionEngine.cash` from the most recent snapshot. This prevents cash from being reset to `STARTING_CAPITAL` after a restart.

### Table: `market_snapshots`

Rolling price tick history. Trimmed to 5,760 rows per symbol (~48 hours at 30-second intervals).

| Column | Type | Notes |
|---|---|---|
| `id` | Integer PK (auto) | |
| `symbol` | String (indexed) | Trading pair |
| `timestamp` | DateTime (indexed) | Tick time |
| `price` | Float | Mid price from Kraken ticker |
| `volume` | Float nullable | Volume (not currently populated) |

On startup, the last 60 ticks per symbol are loaded into `_price_history` deques to give the strategy and indicator module warm-started history.

### Table: `trade_ideas`

Every strategy-generated signal with full context. Written by `repo.save_trade_idea()` on each signal regardless of whether it passes risk evaluation.

| Column | Type | Notes |
|---|---|---|
| `id` | String PK | UUID from `TradeIdea.id` |
| `strategy_id` | String | e.g. `"combined"` |
| `market` | String | Trading pair |
| `direction` | String | `"long"` or `"short"` |
| `thesis` | Text | Human-readable rationale (includes LLM reasoning if available) |
| `supporting_signals` | JSON | Raw indicator values, votes, momentum, ATR, price changes, `pre_llm_confidence` |
| `confidence` | Float | Final confidence after learner + LLM adjustments |
| `entry_plan` / `exit_plan` / `stop_or_invalidation` | Text | Strategy description fields |
| `position_sizing_proposal` | Float | Fraction of equity proposed (0.20 = 20%) |
| `mode_eligibility` | JSON | List of trading modes this signal can execute in |
| `momentum_pct` | Float nullable | Percentage price move that triggered the signal |
| `indicators` | JSON | Full indicator snapshot at signal time |
| `llm_used` | Boolean nullable | Whether the LLM was available |
| `llm_sentiment` | Float nullable | LLM sentiment (-1 to 1) |
| `llm_confidence_scale` | Float nullable | LLM confidence multiplier (0.5–2.0) |
| `llm_reasoning` | Text nullable | LLM reasoning string (max 20 words) |
| `news_context` | JSON nullable | Up to 5 relevant news articles shown to the LLM |
| `risk_approved` | Boolean nullable | Whether the risk engine approved the signal |
| `risk_reason` | Text nullable | Risk engine decision reason |
| `created_at` | DateTime | Signal creation time |

The `GET /api/signals/{trade_idea_id}` endpoint reads from this table and returns all fields for the signal detail modal breakdown.

### Table: `activity_log`

Persisted copy of the activity log. Every bot event written via `activity.info/warn/error/success()` is appended here. Trimmed to keep the 2,000 most recent rows (every 10 ticks).

| Column | Type | Notes |
|---|---|---|
| `id` | Integer PK (auto) | |
| `level` | String | `"info"`, `"warn"`, `"error"`, `"success"` |
| `message` | Text | Primary event description |
| `detail` | Text | Optional context (price, thesis, error string) |
| `timestamp` | DateTime (indexed) | UTC event time |

On startup, the last 200 entries are loaded into the in-memory deque so dashboard history is immediately available.

### Table: `risk_rejections`

Every signal that was blocked by the risk engine. Complements `trade_ideas` (which records all signals including rejected ones) with a fast-path query for the dashboard's Risk Rejections panel.

| Column | Type | Notes |
|---|---|---|
| `id` | Integer PK (auto) | |
| `market` | String | Trading pair |
| `direction` | String | `"long"` or `"short"` |
| `confidence` | Float | Signal confidence at rejection time |
| `thesis` | Text | Signal thesis |
| `reason` | Text | Risk engine rejection reason |
| `trade_idea_id` | String nullable (indexed) | Links to the full signal in `trade_ideas` |
| `timestamp` | DateTime (indexed) | Rejection time |

On startup, the last 50 rows are loaded into the `_risk_rejections` deque (newest first).

## Auto-Migration Logic

`init_database()` in `backend/storage/database.py` runs schema migrations before `Base.metadata.create_all()`:

1. **`open_positions` table** — if it exists without a `position_id` column, the table is dropped and recreated.

2. **`order_records` table** — missing `position_id`, `pnl`, or `trade_idea_id` columns are added via `ALTER TABLE … ADD COLUMN`.

3. **`trade_ideas` table** — missing signal-context columns (`momentum_pct`, `indicators`, `llm_*`, `news_context`, `risk_*`) are added.

4. **`signal_outcomes` table** — missing `trade_idea_id` column is added.

5. **New tables** (`activity_log`, `risk_rejections`, `control_state`, `llm_briefings`, `llm_reflections`) — created by `create_all()` if they don't exist.

No manual migration step is required. There is no downgrade path.
